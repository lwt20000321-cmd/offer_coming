## 一、设计目标与风格判断

### 产品类型与体验目标

网页对话产品。求职者本人先完成邮箱、百炼 Key 与简历，再与小凹在同一入口跟投递、做当日五题、接受催促，并在焦虑时接受安抚。「我的投递」和「我的面经」是同一壳子上的两张内容页，不是第二套后台。进入后用虚拟头像管理简历、Key 和本机退出，不把账号做成设置中心。

体验目标：**安静、留白、像和一个人说话，不像在填招聘系统。** 视觉焦点始终是当前要说的话、当前表格或当前面经正文；催促再狠，壳子也不变色。

### 视觉风格

名称：**浅色空气感对话（卡片 + 编辑式）**。

特征：近白画布；粉/蓝/暖色晕染随指针移动缓慢波动；共用顶栏胶囊切换「初次见面 / 日常对话」；两页都有大标题；表单与输入落在大圆角白卡片上；对话消息左右分栏，像聊天软件：小凹在左、用户在右。中文用系统黑体，行距松。

适用理由：用户第二轮参考明确了顶栏、卡片表单、编辑式五题和底部大输入卡。指针波动只作用在背景，不改催促语气，也不抢文字可读性。

避免：深蓝招聘后台、红底全屏警告、侧栏、把辅导和催促拆成两个可见角色。背景波动不得盖过正文对比度。顶栏不加「Agent」字样；求职者虚拟头像只作账号入口，对话里仍然只有小凹。

### 关键 UX 规则

1. **同一时刻只有一个主操作**：上传页主按钮是「开始对话」或「接上记录」；对话页主操作是发送；投递表主操作是改格子/加行；面经页主操作是上传、展开正文或删除；头像任务栏展开时主操作是三项之一或关闭。不用弹窗代替进入对话、发出消息或已挂后的面经询问（询问出现在对话里）。更换简历/Key 用当前页上的白卡片面板，不新开顶栏页。
2. **壳子稳定，语气写在正文里**：早间温柔催促与晚间狠催都用同一套文章式段落；背景可以随鼠标波动，但不因催促变红。
3. **等待可感知**：发送后对话区立刻出现「小凹正在思考...」，不能空白干等；随后可换成更具体的过程说明，再逐字出字；不用全屏转圈，也不把过程说明放在输入卡下方。
4. **整页不滚，只滚对话**：页面外壳、顶栏、标题、进度与输入卡钉住；只有对话内容区滚动，但不画出滚动条。对话区顶部不再做渐隐虚化。输入框默认单行、插入符垂直居中；字多时增高到约三行后再内部滚动。发送圆钮与输入行垂直居中，不叠在文本框右下角。
5. **失败留在当场**：邮箱未填、未传简历、未贴 Key、Key 被拒绝、JD 读失败、邮件发送失败，都在当前页或当前面板用正文说明，保留已输入内容。完整 Key 从不回显。
6. **空发送不伪造成功**：对话输入为空时发送无效，不插入空气泡。

### 布局、间距与形状

- 内容最大宽度：UI-01 主列 760px；UI-02 / UI-03 / UI-04 主列 1080px。水平边距桌面 28px，窄屏 16px。对话白卡片与「我的面经」「我的投递」白卡片同宽、同高、同位置。对话页心情/时间/Mock 演示贴在页底与顶栏左右齐平，不占白卡片高度。
- 间距刻度：8 / 12 / 16 / 24 / 40 / 64。
- 圆角：顶栏胶囊与主按钮 `999px`；内容卡片与对话消息盒 `32px`（窄屏 24px）；发送圆钮 `999px`。
- 主按钮高度 48px。对话页输入卡不再用 168px 最小高度；输入行与发送圆钮同一行。输入框默认 48px 一行、插入符垂直居中；内容变多时增高至约三行（约 96px），超出后在框内滚动。
- 整页 `html/body/#root` 锁在 `100dvh` 且 `overflow: hidden`。欢迎页 `.stage` 内容过高时可内部滚动；对话页只有 `.chat-thread` 滚动。所有内部滚动区域隐藏滚动条。对话区顶部不做渐隐虚化。
- 共用顶栏：未进入时左为「初次见面」胶囊（「日常对话」可点但会留在本页并提示）。进入后「初次见面」消失，左侧改为虚拟头像 + 「日常对话」胶囊；右仍为「我的面经」「我的投递」，「我的投递」在最右侧。未完成邮箱、简历与 Key 时点右侧两项或「日常对话」，留在初次见面并提示。
- 虚拟头像：直径 40px 圆，Surface 底、Line 描边，内为产品提供的简笔人物（不是小凹 blob、不上传照片）。点头像或其正下方 8px 处展开任务栏。
- 任务栏：Surface、16px 圆角、卡片阴影；三项「我的简历」「我的key」「退出」左对齐、14px/500；「退出」用 Mute，不铺红底。再次点击头像或点页面空白处收起。
- 窄屏：标题改为 32px；卡片内主按钮可单独成行；进入后仍互斥，不得并排。右侧两入口可缩字但不换到第二行挡住头像。

### 层次、阴影与动效

- 静态底晕：左上淡蓝、右下淡粉，始终很淡。
- 指针波动层：粉、蓝、暖色三团径向渐变跟随指针。混合模式 `multiply`。对话页消息列表是圆角白卡片，色晕不压正文；logo、页边、输入卡周围仍可见跟随色。
- 顶、底各一条浅灰「OFFER」循环字带：顶部向左、底部向右，持续滚动；不阻挡点击。字色约 `#D4D4D8`，字号 12px，字距略宽。
- `prefers-reduced-motion: reduce` 时关闭跟随层和字带滚动，只留静态底晕与静止「OFFER」；回复改为整段出现。
- 卡片阴影：`0 20px 60px rgba(10, 10, 10, 0.05)`。
- 催促再狠也不改背景色。

## 四、界面清单与页面设计

### UI-01 欢迎与接续

- **依据与目标**：REQ-001；AC-001、AC-002、AC-021、AC-049。让新人留下邮箱、百炼 Key 和简历；换设备且已有 Key 的人只填邮箱接上；已有简历无 Key 的人补贴 Key。原型：`docs/prototypes/ui-prototype.html#welcome`。
- **布局结构**：共用顶栏（此时左侧是「初次见面」胶囊，无头像）。主列垂直居中：标识 → 标题「小凹，你的专属求职搭子」→ 一句说明 → 白卡片（邮箱行 + Key 行 + 简历行与「开始聊聊」）→ 出题规则说明 → 「只用邮箱接上」。与 UI-02 互斥。
- **内容呈现**：已选文件只显示文件名。Key 用 password 输入，占位「粘贴你的百炼 API Key」。卡片内不放验证码、登录密码。底部可有「下次回来，接着聊。」
- **组件清单**：

| 区域 | 组件类型 | 内容/数据 | 交互表现 | 全局风格引用 |
| --- | --- | --- | --- | --- |
| 顶区 | 标识 | 小凹 | 无跳转菜单 | 标识 |
| 英雄 | 标题+正文 | 先把简历交给小凹 / 一句产品说明 | 只读 | 英雄标题、正文 |
| 表单 | 文本输入 | 收件邮箱 | 必填 | 文本输入 |
| 表单 | 密码输入 | 百炼 Key | 首次必填；已有 Key 的接续模式隐藏 | 文本输入 |
| 表单 | 文件上传区 | 简历 PDF/DOCX/TXT | 首次必选；接续模式隐藏 | 文件上传区 |
| 主操作 | 主按钮 | 开始对话 / 接上记录 | 校验通过且 Key 探测非 401 后进入 UI-02 | 主按钮 |
| 次操作 | 文本链 | 我换了设备，只用邮箱接上 | 切换为只填邮箱（已有 Key 时）；无验证码 | Mute 正文 |

- **状态与操作结果**：
  - 首次空表 → 点开始对话 → 留在本页，邮箱、Key 或简历旁出现 DangerText（AC-002）。
  - 已填邮箱、以 `sk-` 开头的 Key 并选中可用简历 → 点开始对话 → 短暂「正在确认 Key」→ 非 401 则进入 UI-02，顶栏「初次见面」换成头像（AC-001）。401 则不进入，说明 Key 无效。
  - 429/超时 → 仍进入，并在对话或本页提示「这次没连上，先保存了」（D-007-C）。
  - 点「只用邮箱接上」且该邮箱已有简历与 Key → 上传区与 Key 行隐藏，主按钮改为「接上记录」；只填邮箱即可进入（AC-021）。
  - 该邮箱已有简历但无 Key → 必须出现 Key 行，补贴后才能进入（AC-049）。
  - 无效邮箱格式 → 不进入，保留已填内容。
- **示例数据与文案**（仅演示）：邮箱 `lin@example.com`；Key 显示为圆点，不写真实密钥；文件 `林晓_产品简历.pdf`。不展示验证码、登录密码、下载。
- **页面例外**：主按钮文案为「开始聊聊 ↗」或接续时的「接上记录 ↗」。

### UI-02 小凹对话

- **依据与目标**：REQ-002–007、009–011；AC-003–016、AC-018–020、AC-037–041、047–054。在同一对话里完成岗位跟进、五题、催促、辅导、粘贴面经，以及已挂后面经删留询问。顶栏头像负责任务栏。原型：`docs/prototypes/ui-prototype.html#chat`。
- **布局结构**：同一顶栏切到「日常对话」；左侧是虚拟头像而非「初次见面」。主列 1080px，与面经/投递相同：页头一行（小凹标识 + 今日进度）→ 白卡片。标识 56px，向上探出，进度文字与 logo 下沿齐平，页头占位仍与面经标题行同高，因而白卡片与「我的面经」文件区同宽同高同位置。消息与输入都在这张卡里，仅消息区滚动。心情/时间底栏贴在页底与顶栏齐平。头像任务栏与账号面板浮在当前页上，不挤掉输入区。未完成初次见面不可进入。
- **内容呈现**：五题用 1–5 序号 + 来源（共性/岗位），放在小凹左侧气泡里。用户发言靠右，不写「你：」。催促、辅导都是小凹左侧气泡。Key 失效说明是 DangerText 级左侧说明，并提示打开「我的key」。消息区左右内边距相同。
- **组件清单**：

| 区域 | 组件类型 | 内容/数据 | 交互表现 | 全局风格引用 |
| --- | --- | --- | --- | --- |
| 顶栏 | 虚拟头像 | 账号 | 点下方展开任务栏 | 虚拟头像、账号任务栏 |
| 顶栏 | 胶囊 | 日常对话 | 选中 | 顶栏胶囊 |
| 主列 | 标识 | 小凹 | 不打开账号菜单 | 标识 |
| 消息 | 用户气泡 | 岗位链接、进度、答案、情绪 | 发送后立刻出现 | 用户气泡 |
| 消息 | 小凹气泡 | 考查点、题目、点评、辅导、催促、邮件失败说明 | 先过程说明再逐字 | 小凹气泡、弱标签 |
| 对话区 | 过程说明 | 小凹正在思考... / 正在读取岗位链接 | 发送后立刻显示，出字后消失 | 过程说明 |
| 底栏 | 文本输入+发送 | 用户一句话 | 「和小凹说说...」；空内容禁用发送圆钮 | 输入卡片、发送圆钮 |

- **状态与操作结果**：
  - 发送岗位链接 → 过程说明「正在读取岗位链接」→ 考查点或失败说明；稍后一句「已收入该岗位面经」或失败说明（AC-003/004/037/038）。过程说明不出现主体/子 Agent 字样（AC-041）。
  - 对话里粘贴面经 → 过程说明「正在收录面经」→ 一句入库，打开「我的面经」能看到。文件改在「我的面经」上传（AC-039）。
  - 发送情绪（不开心/焦虑）→ 走心辅导气泡，可带「正在辅导」；此时不插入骂醒式催促气泡（AC-013/019）。
  - 用户说心情变好了 → 结束辅导标签，紧接着题目或催促（AC-014）。
  - 整点催促：插入小凹气泡，早间文案温柔、晚间文案更狠，页面背景不变（AC-007/008）。
  - 邮件失败：对话里催促仍在，另有一句 DangerText 级说明（AC-016）。
  - Key 无效：对话说明请到「我的key」更新；不出现假装成功的模型回复（AC-054）；整点另可发模板邮件（D-009-B）。
  - 点头像下方 → 任务栏三项（AC-050）。点「我的简历」→ 面板显示当前文件名并可换文件（AC-051）。点「我的key」→ 面板不显示旧 Key，可粘贴新 Key（AC-052）。点「退出」→ 回 UI-01，本机不再自动进（AC-053）。
  - 空输入点发送 → 无新消息。
  - 岗位改为已挂且有相关面经（对话或从表页跳回）→ 小凹说明哪些面经局部仍有用、建议删哪些，并询问；未回答前条目仍在「我的面经」（AC-047/048，D-006-A）。
- **示例数据与文案**（仅演示）：岗位「星云科技 产品经理」；链接示例 `https://jobs.example.com/pm-32`；五题只显示题干，不标「简历深挖 · 共性题」；早间催促「今天这五题，我们慢慢写，我在。」并附题干；晚间催促「还没答完。十二点以前，把五题写完。」；点评后再给题型、对准岗位和考查点。Key 失效「请到我的key更新后再聊。」邮件正文与催促同一套，不写进度表。
- **页面例外**：对话页不使用英雄标题；消息与输入合为一张四角圆角白卡片，中间无第二张卡的交接。账号面板盖住部分内容但不改对话壳。

### UI-03 我的投递

- **依据与目标**：REQ-008、003；AC-022–028、045、047。在顶栏最右侧打开投递表，改格子、加行、删行；面试时间可空。原型：`docs/prototypes/ui-prototype.html#apps`。
- **布局结构**：同一顶栏，右侧「我的投递」选中。主列 1080px：标识（可选缩小）→ 页题「我的投递」+ 一句说明 → 白卡片表格。整页不滚浏览器；卡片内表格可横向/纵向滚并隐藏滚动条。未完成初次见面不可进入。
- **内容呈现**：列固定为公司、岗位、投递链接、投递时间、面试时间、投递状态、面试总结。链接可换行。面试总结长文在格内截断，聚焦后展开编辑。不加筛选、搜索、导出。
- **组件清单**：

| 区域 | 组件类型 | 内容/数据 | 交互表现 | 全局风格引用 |
| --- | --- | --- | --- | --- |
| 顶栏 | 右侧胶囊 | 我的投递 | 与日常对话齐平，在最右侧 | 顶栏胶囊 |
| 主列 | 页题 | 我的投递 | 只读 | 正文 16 / 标题 24px 600 |
| 表格 | 可编辑单元格 | 七列岗位数据 | 失焦保存；状态改为已挂且有面经则立刻回对话 | 投递表 |
| 表下 | 次按钮 | 加一行 | 新行投递时间默认当天，面试时间空 | Pill 胶囊 |

- **状态与操作结果**：

  - 改某一格并离开 → 刷新或再打开仍是改后内容（AC-024）。
  - 加一行未填投递时间 → 默认当天北京日期（AC-028）。
  - 清空面试时间 → 不按截止日加急（AC-045）。
  - 状态改为已挂且该岗有面经 → 立刻切到日常对话，看到删留询问（D-006-A / AC-047）。无相关面经则留在本页。
  - 删除一行 → 行消失，不再出题（AC-025）。
- **示例数据与文案**（仅演示）：星河一面 · 一面 · 面试时间 周五；青禾渠道增长 · 简历筛选中；数据岗 · 已挂。
- **页面例外**：主列宽于对话页；不用英雄大标题。

### UI-04 我的面经

- **依据与目标**：REQ-010；AC-037–044、046。查看已收录列表和正文，可手删；标题旁上传面经。原型：`docs/prototypes/ui-prototype.html#jingyan`。
- **布局结构**：同一顶栏，右侧「我的面经」选中、在「我的投递」左侧。主列 1080px：页题「我的面经」与「上传面经」同一行 → 白卡片条目列表。卡片底边与底部 OFFER 字带留出空隙。未完成初次见面不可进入。
- **内容呈现**：每条有标题、来源（检索 / 上传 / 粘贴）、关联岗位、可展开正文。空列表是一句说明，不是报错。
- **组件清单**：

| 区域 | 组件类型 | 内容/数据 | 交互表现 | 全局风格引用 |
| --- | --- | --- | --- | --- |
| 顶栏 | 右侧胶囊 | 我的面经 | 与日常对话齐平 | 顶栏胶囊 |
| 页题行 | 标题 + 次按钮 | 我的面经 / 上传面经 | 点按钮选文件，收录后出现在列表顶部 | 标题 24px 600；Pill 胶囊 |
| 列表 | 面经条目 | 标题、来源、正文 | 点开展开正文；删除后立刻消失 | 面经条目 |
| 空状态 | 正文 | 还没有收录的面经 | 只读，引导点上方上传 | Mute 正文 |

- **状态与操作结果**：
  - 未完成邮箱、简历与 Key 点入口 → 留在 UI-01 并提示（AC-043）。
  - 检索或本页上传入库后打开本页 → 能看到对应条目和正文（AC-037/039）。
  - 检索失败 → 本页不出现伪造条目（AC-038）。
  - 删除一条 → 列表与正文消失，刷新后仍不在（AC-046）。
  - 无条目 → 空状态，不崩溃（AC-044）。
  - 本页标题旁有「上传面经」；日常对话不再放面经附件。
- **示例数据与文案**（仅演示）：「星河一面：激活指标怎么问」来源检索；「你上传的渠道面经.pdf」来源上传。
- **页面例外**：主列宽于对话页；不用英雄大标题；页题下不再放「本页没有上传」说明。

## 五、使用与验收

应采用：浅底、指针跟随的淡色波动（对话消息区除外）、顶左底右浅灰「OFFER」循环字带、未进入时顶栏「初次见面」、进入后左侧虚拟头像 + 日常对话、右侧面经/投递、欢迎页大标题与 Key 行、各页同一 blob 标识（对话角色）、白卡片表单/输入/表格/面经列表、左右分栏聊天气泡（小凹左、用户右）、文章式五题仍在小凹侧、对话区内过程说明 + 逐字回复、整页不滚仅内容区滚。

应避免：招聘后台密度、红底恐吓整页、用弹窗代替发送结果或已挂询问、空发送假装成功、背景波动盖住文字、对话页再放面经附件、回显完整 API Key、把账号头像画成第二个小凹、消息通栏左对齐分不清谁在说。

文档检查：UI-01–UI-04 均有布局、组件、状态与示例；无账号注册密码、无 Excel 导出。

原型验证（阶段 B）：本轮待用户确认欢迎 Key 行、进入后头像任务栏、我的简历/我的key 面板与退出。实现后须在真实页面再核：三样门禁、换设备只填邮箱、头像三项、Key 不回显、退出回欢迎。旧项（顶栏齐平、投递表、面经上传）沿用 2026-09-14 确认。
