## D-001 再次打开时如何认出同一求职者

- **日期与状态**：2026-09-13；已确认。
- **关联**：REQ-001、AC-001、AC-002、AC-017、AC-021；API-001、API-002、API-003；tech-spec §二、§三、§五；PRD 流程图「接续令牌 / 填邮箱」。
- **问题与体验影响**：PRD 要求用上传时填写的邮箱作为联系和识别依据，且不做完整注册/密码体系。关掉网页再打开要接上同一份简历、投递和当日任务。不同认出方式会改变「要不要再填邮箱」「换一台设备能不能接上」「知道邮箱的人能不能看到你的材料」。

| 可选方案 | 用户体验与代价 | 技术依据或待验证项 |
| --- | --- | --- |
| A. 同浏览器自动接续；换设备只需填同一邮箱，不必再传简历，也不做验证码 | 关掉再打开几乎无感。换电脑/清缓存时填一次邮箱即可。任何填对邮箱的人都能看到该邮箱下的简历、投递和对话。 | 前端 `localStorage` 保存 `session_token`；后端邮箱唯一对应一名求职者。无密码，识别强度等于「知道邮箱」。 |
| B. 每次打开都填邮箱再进入对话，浏览器不自动记住 | 比 A 多一步，换设备体验与同设备相同。隐私代价与 A 相同：填对邮箱即可进入。 | 不依赖本地存储；仍发短期 `session_token` 供本次打开使用。 |
| C. 换设备或过期后向该邮箱发一次性验证码，通过后再接续 | 多等一封邮件、多输入一步；别人只知道邮箱还进不去。依赖邮件通道可用。邮箱填错或邮件进垃圾箱时，用户会卡住。 | 需真实发信。验证码 10 分钟有效、一次性。未采纳，不进入契约。 |

- **建议及理由**：建议 **方案 A**。PRD 强调关掉再打开直接接上、且明确不做密码体系；A 对主路径摩擦最小。换设备仍可用同一邮箱接上。邮箱等于通行证，不是账号保险柜。
- **最终选择与确认依据**：方案 A。2026-09-13 用户原话「按建议」，由编排器回传 Solution Designer。
- **落地与验收**：tech-spec API-001/002 主路径；PRD AC-017（同浏览器自动接续）、AC-021（换设备填邮箱、无验证码）。测试尚未执行。
- **复议条件**：若后续要求防止他人凭邮箱查看简历，需重议（可能回到 C）。

- **复议条件**：若目标模型或网络无法稳定支持 SSE，可退回 A，不改变对话内容规则。
- **2026-09-15 补充确认**：用户要求全部小凹文字流式输出，且出字前必须有缓冲提示，不能干等。沿用方案 B，默认缓冲句改为「小凹正在思考...」。

## D-007 保存百炼 Key 时要不要立刻向百炼试一下

- **日期与状态**：2026-09-14；已确认。
- **关联**：REQ-001、REQ-011；AC-001、AC-049、AC-052、AC-054；API-001、API-002、API-017；tech-spec §二 API-001/002/017、§五、§六；EXT-001。
- **问题与体验影响**：用户把 Key 贴进初次见面或「我的key」。若保存前向百炼发一次最小请求，会多等几秒、并在用户自己的账上产生一次很少量调用；输错的 Key 进不了对话。若只检查「是不是以 sk- 开头」，进入很快，但第一次对话或整点催促才会发现 Key 不能用（AC-054）。5xx/超时若被当成「Key 无效」，用户会被误拒。

| 可选方案 | 用户体验与代价 | 技术依据或待验证项 |
| --- | --- | --- |
| A. 保存时必须探测成功才写入。401 或网络失败都不让进、不覆盖旧 Key | 错 Key 进不去。百炼抖动时，即使用对的 Key 也会卡在门口。多等约 2–10 秒，用户 Key 被扣一次很少量调用。 | `GET {llm_base_url}/models` 或 `chat/completions` 且 `max_tokens=1`。[百炼 401 invalid_api_key](https://help.aliyun.com/zh/model-studio/error-code)。 |
| B. 只做格式检查（去空格、须以 `sk-` 开头），立刻保存并进入 | 开门最快。贴成过期/删掉的 Key 也能进对话，发第一条或等到整点才看到「请到我的key更换」。 | 不在保存路径调百炼。AC-054 仍成立。 |
| C. 保存时探测：仅 401/`invalid_api_key` 拒绝保存；429/5xx/超时仍写入，并提示「这次没连上，之后若失败再到我的key」 | 错 Key 进不去。网络不好时仍能进，之后按 AC-054 再说。仍有一次探测等待和少量费用。 | 与 A 同一探测；不把瞬时故障标成 `invalid`。 |

- **建议及理由**：建议 **方案 C**。能挡住明显贴错，又不把百炼抖动当成「你的 Key 坏了」。
- **最终选择与确认依据**：方案 C。2026-09-14 用户确认「全部采用建议项」，由编排器回传 Solution Designer。
- **落地与验收**：API-001/002（补贴 Key）/017 保存前探测。仅 401/`invalid_api_key` → 400 `LLM_KEY_INVALID`，不写入。429/5xx/超时仍加密保存，`llm_key_probe_status=unreachable`，用户看到「这次没连上」。错 Key 进不了对话。测试尚未执行。
- **复议条件**：探测费用或等待被投诉；或百炼 `GET /models` 在该兼容域名不可用且 1 token 调用过重。

## D-008 点「退出」时，服务端这张接续令牌要不要作废

- **日期与状态**：2026-09-14；已确认。
- **关联**：REQ-011；AC-053；API-018；tech-spec §二 API-018、§五。
- **问题与体验影响**：PRD 要求退出只清本浏览器接续、不删档，同一邮箱仍能进。若只删浏览器里的 token，这张令牌在过期前仍能被拷走使用。若同时作废这一张，同一浏览器其它标签也会掉线，但其它设备不受影响。若作废该邮箱下全部会话，换过设备的窗口也要重新填邮箱，和「只清本机」不完全一致。

| 可选方案 | 用户体验与代价 | 技术依据或待验证项 |
| --- | --- | --- |
| A. 只删除本机 `localStorage` 里的 token，服务端这张令牌在 TTL 内仍有效 | 退出立刻回到初次见面。谁拷走过 token，在过期前仍能当这个人。实现最少。 | 不新增接口。 |
| B. 退出时 DELETE 当前这张 token（API-018），其它设备上其它 token 仍有效 | 本机（含其它标签）不再自动接上。别人拿不到这张作废令牌。换设备填邮箱仍能进。 | API-018；只删当前 `token_hash`。 |
| C. 退出时作废该邮箱下全部会话 | 所有设备都要重新填邮箱。更像「登出所有装置」，和「只清本机」不完全相符。 | 未作为默认。 |

- **建议及理由**：建议 **方案 B**。符合「清掉本浏览器接续」，又真正让这张通行证失效。
- **最终选择与确认依据**：方案 B。2026-09-14 用户确认「全部采用建议项」，由编排器回传 Solution Designer。

## D-009 求职者 Key 失效时，整点催促邮件怎么处理

- **日期与状态**：2026-09-14；已确认。
- **关联**：REQ-004、REQ-007、REQ-011；AC-015、AC-016、AC-054；调度；EXT-003。
- **问题与体验影响**：整点催促文案须由投递催促模型生成，且必须用该求职者 Key，不能改用运营 Key。Key 已经无效时，无法生成骂醒催促。人若没打开网页，只写对话说明可能看不到；发固定模板邮件能提醒去换 Key，但不是原来的进度催促。

| 可选方案 | 用户体验与代价 | 技术依据或待验证项 |
| --- | --- | --- |
| A. 只在对话插入「请到我的key更新」；本整点不发邮件、不调模型 | 打开网页能看到。当天没打开网页的人，可能不知道催促停了。 | 调度跳过 EXT-001 与 EXT-003。 |
| B. 对话插入说明，并另发一封**固定模板**邮件：「你的百炼 Key 已失效，今日催促和出题发不出来，请到小凹「我的key」更新。」不生成骂醒文案 | 不在电脑前也能知道要去换 Key。邮箱里出现的不是日常狠催，而是运维说明。 | EXT-003 固定正文；不调投递催促模型。 |
| C. 用规则模板（非模型）继续发对话+邮件催促，仍不出题 | 还能被催进度，但催促文案不再由投递催促模型生成，和已确认 REQ-004 不完全一致。 | 未作为默认。 |

- **建议及理由**：建议 **方案 B**。AC-054 要求用户看到须更新 Key；人可能靠邮件才知道。不拿运营 Key 代写骂醒催促。
- **最终选择与确认依据**：方案 B。2026-09-14 用户确认「全部采用建议项」，由编排器回传 Solution Designer。
- **落地与验收**：Key 无效或缺失的整点：不调模型、不发骂醒催促；对话插入 `error_notice`；当日至多一封固定模板邮件（正文见 tech-spec EXT-003）。SMTP 失败不回滚对话说明，下一整点可再试发直到当日已成功或窗口结束。测试尚未执行。
- **复议条件**：用户觉得说明邮件太吵，或希望完全静默直到打开网页。
